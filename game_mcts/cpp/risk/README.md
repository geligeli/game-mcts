# Risk (`cpp/risk/`)

A full-size stochastic game (Risk) built on the game framework in the
[game-mcts](https://github.com/geligeli/game-mcts) repo
(`game_mcts/cpp/mcts/`, consumed as the `@game_mcts` Bazel module) — see
that repo's `game_mcts/cpp/mcts/README.md` for the concepts (`Game`,
`ChanceGame`, `ActionProposer`, rollouts, tournaments) this module
implements.

## Pieces

- `risk_game.h` / `risk_game.cpp` — `risk_game::RiskState<N>`: the game
  state and transition function (phases, dice battles as chance nodes,
  `apply_action_in_place`, `sample_action`, `is_valid_action`).
- `risk_board.h` — the static board: territories, adjacency, continents.
- `risk.proto` — `RiskState` / `RiskAction` protos; `risk_serialization.h`
  provides the `mcts::GameSerializationTraits` specialization that enables
  tree export, trajectory recording and the Python bindings.
- `ascii_board.h` — ascii renderer for the board (used by the self-play
  binary and the HTML tree plots).
- `strategies/risk_proposer.h` — `RiskProposer<N>`, a custom
  `mcts::ActionProposer` + `BoundedProposer` for Risk's huge action space:
  `sample()` draws one action without enumerating, `propose()` builds a
  `DedupSampler` whose exhaustion bound comes from `support_size()`.
- `strategies/risk_rollout_shortcuts.h` — rollout shortcut resolving dice
  battles with a precomputed expected-outcome table
  (`strategies/expected_battle_outcomes.h`, generated by
  `predict_battle_outcome_gen.cpp`) instead of sampling. Used for the
  `expected` rollout mode; the tree itself always samples the exact rules.

## Binaries

- `risk_mcts_selfplay.cpp` — reference self-play loop: per-player MCTS
  parameter overrides via `--player_params='iterations=400,rollout=exact;...'`,
  an alternate-screen ascii renderer, move recording into `RiskTrajectory`
  protobufs (`--record_games=/tmp/games`), per-move timing. Interactive:
  space pauses/resumes; while paused `s` dumps the current state as
  protobuf-text and `a` dumps the ascii board; `q` quits.

  ```
  bazel run //game_mcts/cpp/risk:risk_mcts_selfplay -- --iterations_per_move=100 --delay_ms=200
  ```

- `risk_tournament.cpp` — multithreaded round-robin with ELO ratings, driven
  by a config file (see `example_tournament.cfg`).
- `risk_game_benchmark.cpp` — google-benchmark for transitions and rollouts.

## Python bindings

`risk_pybind.cpp` builds the `risk_engine` module (`Game`, `MctsSearch`,
`new_game`, `new_mcts`) on top of the framework's `py_game.h` / `py_mcts.h`
(game-mcts repo);
`risk_engine_test.py` shows how to drive a game and a search from Python
with serialized `RiskState` / `RiskAction` protos.
